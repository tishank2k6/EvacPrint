Chapter 07

System architecture

One grid, one engine, many views.

Everything except the AI path runs inside the browser. If the internet is down, only the AI assistant and AI drafting stop working.

7.1How data flows — one simulation run

  1. Layout. Hall 406 is built by createHall406(); a custom venue's shapes are converted by rasterize(). Both produce the same layout object: a grid of cell types + named openings + metadata.
  2. Compile. compile() derives passable cells, seat cells, standing cells and groups of door/exit cells with their widths.
  3. Simulation. The controller creates new Simulation(layout, params): agents placed on seats (seeded random shuffle), Dijkstra fields computed for every open exit.
  4. Loop. Each animation frame the controller calls step() one or more times (depending on 1×–8× speed). Each step = 0.1 s of simulated time.
  5. Views. The 2D plan, 3D view, KPIs and charts read positions, states, density and exit counters from the same object — so they can never disagree.
  6. Summary. When everyone is out (or 600 s pass), summary() returns every number shown in the UI: RSET, t50, t95, peak density, exit counts, bottlenecks, curve, per-agent outcomes. analyzeRisk() turns it into findings.
  7. What-if. Recommendations serialize the layout variants and send them to Web Workers, which run runHeadless() and post results back for ranking.
  8. Persist. Reports go to localStorage; venues to IndexedDB.

7.2How the AI path works

Browser panel → POST /api/assistant/chat with the conversation + a JSON snapshot of the app state → our Node handler adds the system prompt (EvacPrint facts, safety rules) and tool definitions → Gemini streams back text and/or a function call (e.g. what_if) → the browser shows a confirmation card for actions that change anything → on Confirm, the browser executes the tool on a copy and sends the result back → Gemini explains the result. The API key never leaves the server.

8.1Grid conversion (digitising the venue)

What: the venue becomes a grid of 0.5 m × 0.5 m cells, each typed as outside, floor, wall, seat, obstacle, door, exit or stage. Why: every later computation (paths, density, 3D extrusion) needs a common, discrete map. Where: createHall406() in layout.js; rasterize() in model.js for custom venues. Example: like turning a photo into pixels — the plan becomes a mosaic where each tile says what is there. Hall 406 is a 52 × 39 cell grid.

8.2Multi-source Dijkstra distance field

What: Dijkstra's algorithm finds the lowest-cost path in a graph. We run it "backwards" from every cell of an exit at once (multi-source), so the result is a map giving every cell's cost to reach that exit.

Why: 200 people need routes simultaneously. One map per exit answers "which way, and how far?" for everyone in one pass.

How: start with the exit cells at cost 0 in a min-heap. Repeatedly take the cheapest unsettled cell and relax its 8 neighbours: straight step 0.5 m, diagonal 0.5·√2 ≈ 0.71 m — diagonals only if both side cells are open (no corner cutting). Cells next to walls cost ×1.25, so people keep a little distance from walls. Every 2 s the costs are multiplied by a congestion factor (1 + 0.45·density), so routes bend away from queues.

Use: each agent walks "downhill" along the field's gradient (interpolated between cells for smooth motion).

Real-world exampleThink of the exit as the bottom of a valley and the cost map as the height of the land. Water poured anywhere flows downhill to the exit. Agents are the water. A queue at a door is like a pile of sand that raises the land there, so new water finds another valley.
// simplified from src/sim/pathfinding.js
function distanceField(grid, exitCells, congestion, wallPenalty) {
  dist = Infinity for every cell;  heap = MinHeap()
  for (c of exitCells) { dist[c] = 0; heap.push(0, c) }
  while (heap not empty) {
    [d, c] = heap.pop();  if (d > dist[c]) continue      // stale entry
    for (n of 8 neighbours of c that are passable) {
      if (diagonal and a side cell is blocked) continue // no corner cutting
      step = (diagonal ? 0.5*√2 : 0.5) * congestion[n] * wallPenalty[n]
      if (d + step < dist[n]) { dist[n] = d + step; heap.push(dist[n], n) }
    }
  }
  return dist   // metres-equivalent cost from every cell to this exit
}

8.3Exit choice with hysteresis

Each moving agent compares the cost of every open exit from its current cell and picks the lowest. To stop people flip-flopping between two doors, it only switches if the new exit is clearly better: at least 15 % cheaper and 1.5 m shorter (chooseExit()). In Venue Studio, wheelchair users ignore exits marked not step-free (if an accessible one is reachable), and occupants unfamiliar with the building add a 4–18 m penalty to every exit except the main entrance (smaller penalty with good signage). Example: you will not walk to a farther door just because it is 20 cm shorter, but you will if the near door has a long queue.

8.4Agent-based modelling (ABM)

What: instead of treating the crowd as a fluid, every person is a separate "agent" with their own properties and state.

Properties: free walking speed (adults 1.34 ± 0.15 m/s, clipped 1.0–1.6; reduced mobility and wheelchair 0.7–1.0 m/s), body radius (0.22 m adult, 0.23 m reduced mobility, 0.36 m wheelchair), reaction time (default 10–30 s), target exit, category.

States: Waiting (reacting to the alarm) → Moving (walking or queuing) → Evacuated (exit time logged), or Trapped if no exit is reachable.

Why: individual differences (a slow person in a narrow aisle) create the real-world effects we want to measure.

8.5Movement: speed–density + relaxation

Every 0.1 s each moving agent: (1) reads the direction from its exit's field; (2) measures the crowd density around it (excluding its own contribution); (3) computes desired speed = free speed × Weidmann factor (never below 6 % so nobody freezes completely); (4) adjusts its velocity smoothly towards the desired one with a 0.5 s relaxation time, like a person accelerating rather than teleporting. Under panic, desired speed is multiplied by (1 + 0.3 × panic).

8.6Collision resolution

People are discs that may not overlap. After moving, agents are put into grid "buckets"; for each nearby pair that overlaps, both are pushed apart (moving agents more than seated/waiting ones). This is done in three passes per step (Gauss–Seidel style) so bodies stay separated and densities saturate near the physical limit. Agents are also pushed out of walls and furniture. Example: like marbles in a tray — shaking them makes them settle without overlapping.

8.7Door capacity: token-bucket gates

Each door/exit has a "bucket" that refills at width × 1.33 tokens per second (SFPE specific flow) and holds at most 1 token. An agent stepping into an opening it has not passed yet needs a token; if none is available, it steps back and waits (shown red, counted in the queue). Example: a turnstile that lets one person through every 0.75 s for a 1 m door. Doubling the width doubles the refill rate.

Faster-is-slower (panic clogging): when panic > 0 and the density in front of the door exceeds 2.5 p/m², the refill rate is reduced by up to 45 % × panic — a simplified (phenomenological) version of the clogging effect described by Helbing et al. (2000): rushing crowds jam doors.

8.8Density estimation and the heatmap

For every moving agent, the engine adds a small Gaussian "bump" (radius R = 0.7 m, total volume 1 person) to the cells around it. Summing all bumps gives a smooth density field in persons/m². This is smoothed over time with a 1 s exponential moving average so the heatmap does not flicker, and each cell's highest value ("peak map") is kept for the end-of-run heatmap. Colours follow Fruin's walkway levels of service: Low < 1.08, Moderate 1.08–2.15, High 2.15–4.0, Critical ≥ 4.0 p/m².

8.9Bottleneck detection

  1. Threshold: every step, a cell whose smoothed density is ≥ 2.15 p/m² (LOS F) accumulates "exposure" seconds.
  2. Group: after the run, cells with ≥ 3 s of exposure are grouped into connected zones (8-neighbour flood fill); zones smaller than 2 cells are ignored.
  3. Describe: each zone gets its area, peak density, total exposure (cell·seconds) and a name from the nearest landmark ("Door C approach").
  4. Rank: by exposure × peak — long-lasting and severe crowding first.

Live markers during the run use the same grouping on the current smoothed density (cells now ≥ 2.15 p/m²), without the 3-second rule.

8.10Recommendation engine

  1. Baseline: run the current layout on 3 seeds (seed, seed+1, seed+2).
  2. Generate candidates from the layout itself: unblock each closed opening; widen each door/exit by 1 m; Hall 406 design options (add a 1 m west emergency exit, relocate the AV console, widen centre aisles to 1.5 m, shorten the stage); remove the rear seat row. Custom venues also get: an extra exit on the wall farthest from existing exits, moving obstacles near openings, new aisles, step-free exits, re-opened routes.
  3. Re-simulate every candidate on the same 3 seeds (same people, same seats, same reaction times) in Web Workers.
  4. Compare: for each seed, seconds saved = baseline RSET − candidate RSET.
  5. Rank by mean seconds saved. Mark "Helps on every seed" only if the minimum saving > 0 and the mean ≥ 1.5 s; otherwise "Within run-to-run noise". Flag changes that target the worst bottleneck; attach a trade-off note.
Why three seeds?A single run can be lucky. Using the same three random populations for every option is a fair A/B test: the only difference between runs is the design change. The seeded random generator (mulberry32) makes every run reproducible.

8.11Risk-analysis rules

After a run, analyzeRisk() applies transparent rules to the measured result: density zones (high if peak ≥ 4 p/m²), exits whose peak 5-second discharge reaches ≥ 85 % of capacity with ≥ 10 users, closed openings and hazard zones, narrow busy passages (< 1.2 m), unbalanced exit use (one exit carrying > 1.6× its fair share), wheelchair users stuck or among the last 10 % out, people not evacuated, longest travel distance vs a 45 m reference, and delayed areas (mean exit time > 1.35× overall).

8.12Other algorithms in the codebase

  • Seeded pseudo-random generator (mulberry32) — reproducible populations.
  • Box–Muller normal sampling for walking speeds (rng.normal), clipped to plausible ranges.
  • Threshold wall tracing on calibrated plan images: dark-ink fraction or line-crossing tests per cell, plus a thinning pass.
  • Flood fill to turn traced walls into an enclosed floor area (without leaking through door gaps up to about 2 m).
  • DXF parsing of LINE, LWPOLYLINE, POLYLINE and ARC entities into wall segments using the file's unit code.
  • Quick-room layout generator — places seating blocks with side and centre aisles and spreads exits evenly along the free stretches of each wall.
Chapter 09

The mathematics

Only formulas that are actually in the code. Each comes with variables, units and a worked example.

v(ρ) = v₀ · [ 1 − e−γ (1/ρ − 1/ρmax) ]WEIDMANN (1993) SPEED–DENSITY · engine.js weidmannFactor()

v walking speed (m/s) · v₀ the agent's free speed (m/s) · ρ local density (persons/m²) · γ = 1.913 (dimensionless fit constant) · ρmax = 5.4 p/m² (density at which walking stops). For ρ ≤ 0.05 the factor is 1; for ρ ≥ 5.4 it is 0; the engine never lets it drop below 0.06.

Effect: the denser it gets, the slower everyone walks — which is why queues form and grow.

Example: v₀ = 1.34 m/s, ρ = 2.15 p/m² → 1/2.15 − 1/5.4 = 0.465 − 0.185 = 0.280 → e−1.913 × 0.280 = e−0.536 = 0.585 → factor = 0.415 → v = 1.34 × 0.415 ≈ 0.56 m/s. At the start of LOS F, people already walk at less than half their normal speed (the Technology page marks this point).
Q = qs · W , qs = 1.33 persons / (s·m)DOOR DISCHARGE CAPACITY (SFPE SPECIFIC FLOW) · gateRate = widthM × specificFlow

Q maximum flow through an opening (persons/s) · qs specific flow · W clear width (m).

Example: Door C is 1.0 m → Q = 1.33 p/s, i.e. one person every 0.75 s. In the Normal run 78 people used Door C, so even with no walking at all the door needs at least 78 ÷ 1.33 ≈ 59 s of discharge. Widening it to 2.0 m doubles Q to 2.66 p/s. Lobby exit and North fire stair (2.0 m) = 2.66 p/s; West stair (1.5 m) = 2.00 p/s.
ρ(c) = Σagents (1 / πR²) · e−d²/R² , R = 0.7 mGAUSSIAN-KERNEL LOCAL DENSITY · engine.js (Helbing, Johansson & Al-Abideen 2007)

ρ(c) density at cell centre c (persons/m²) · d distance from the agent to the cell centre (m) · R kernel radius (m). Each agent contributes a smooth bump that integrates to 1 person.

Example: one agent standing exactly on a cell centre contributes 1/(π × 0.49) ≈ 0.65 p/m² to that cell. When computing its own speed, the engine subtracts about 0.55 so a person is not slowed by themselves.
ρ̄ ← ρ̄ + (ρ − ρ̄) · (1 − e−Δt/τ) , Δt = 0.1 s, τ = 1 sEXPONENTIAL SMOOTHING OF DENSITY (heatmap, routing, bottlenecks)

Each step moves the smoothed value ρ̄ about 9.5 % of the way towards the instantaneous value ρ — like a 1-second "memory". Prevents flicker and one-frame false alarms.

cost multiplier = 1 + k · ρ̄ , k = 0.45 · (1 − 0.7 · panic)CONGESTION-AWARE ROUTING · updateFields() every 2 s

Cells with crowds become "more expensive" in the Dijkstra field, so agents may re-route to a less busy exit. Panicked crowds re-route less (k smaller).

Example: panic 0.2 → k = 0.45 × 0.86 = 0.387. A cell at 4 p/m² costs 1 + 0.387 × 4 = 2.55× a free cell.
v ← v + (vdes − v) · Δt / τ , τ = 0.5 s; x ← x + v · ΔtFIRST-ORDER RELAXATION (ACCELERATION) AND POSITION UPDATE

vdes = direction × v₀ × (1 + 0.3·panic) × Weidmann factor. With Δt/τ = 0.2, each step closes 20 % of the gap between current and desired velocity.

Example: standing still (v = 0) with vdes = 1.34 m/s → after 1 step 0.27 m/s, after 5 steps (0.5 s) ≈ 0.90 m/s, after 1 s ≈ 1.20 m/s.
treact = [ rmin + (rmax − rmin) · ū ] · (1 − 0.35·panic) · mprofilePRE-MOVEMENT (REACTION) TIME · ū = average of two uniform randoms

Default rmin = 10 s, rmax = 30 s. Averaging two random numbers makes middle values more likely than extremes. Reduced-mobility and wheelchair users get m = 1.15 by default; the wizard sets profile-specific multipliers (e.g. staff 0.5, seniors 1.2).

Example: ū = 0.5, panic 0.2 → (10 + 20 × 0.5) × 0.93 = 18.6 s before this adult starts moving.
clog = 1 − 0.45 · panic · clamp( (ρfront − 2.5) / 2.5 , 0, 1 )FASTER-IS-SLOWER DOOR CLOGGING · multiplies the door's token refill rate

ρfront = highest density within 1 m in front of the opening.

Example: panic 0.3, ρfront = 5 p/m² → clog = 1 − 0.45 × 0.3 × 1 = 0.865 → a 1 m door drops from 1.33 to 1.15 p/s.
RSET = texit(last person) ; t50, t95 = 50th / 95th percentile of exit timesEVACUATION TIME · summary()

RSET (Required Safe Escape Time, as used in fire engineering) is measured, not calculated by a formula: the engine logs every person's exit time; RSET is the largest. If someone is still inside at the 600 s limit, RSET is reported as incomplete. Also reported: mean walking time and mean queuing time.

Example (Normal): RSET = 93.6 s, t95 = 88.6 s. The last 5 % (10 people) took 5 extra seconds — typically the people stuck at the back of the Door A and Door C queues.
share = nexit / N ; peak flow = max5-s bins(passes) / 5 ; utilisation = peak flow / QEXIT UTILISATION · summary() and risk.js
Example (Normal): Door C: 78 of 200 people → 39 % share; peak flow 1.20 p/s ÷ 1.33 = 90 % utilisation → flagged "operating at capacity". A 5-s bin can briefly show slightly more than capacity (e.g. 1.40 of 1.33) because the gate can hold one stored token.
exposure(zone) = Σcells seconds at ρ̄ ≥ 2.15 ; area-time (m²·s) = cell·s × 0.25BOTTLENECK SEVERITY · rank = exposure × peak density
Example (Normal): B1 Door C approach: peak 6.00 p/m², 1656 cell·s → 6.00 × 1656 = 9936; B2 Door A approach: 5.33 × 1849 = 9855 → Door C ranks first.
Δi = RSETbase,i − RSETchange,i (i = 1..3) ; significant ⇔ min Δi > 0 and mean Δi ≥ 1.5 sRECOMMENDATION RANKING · recommend.js rank()
Example (Normal): "Add a 1.0 m emergency exit on the west wall" saved 10.5 to 22.2 s across the 3 seeds, mean 17.3 s → consistent. "Shorten the stage" ranged −3.7 to +8.4 s → within noise, even though its mean (2.8 s) equals "widen Door C".
Diagonal step = 0.5 · √2 ≈ 0.707 m ; wall-adjacent cell cost × 1.25GRID GEOMETRY · pathfinding.js

Straight moves cost 0.5 m (one cell). The wall penalty makes routes keep a little distance from walls, as people do.

A sanity check you can do on a whiteboard (not used by the engine) Lower bound for one door: t ≳ reaction time + people ÷ door flow. For the Normal run, Door A carried 84 people: 84 ÷ 1.33 ≈ 63 s of pure discharge, plus ≈ 10–30 s of reaction — so about 75–95 s is plausible, and the engine measured 93.6 s for the whole hall. This hand estimate is only a cross-check; the simulation adds walking, queuing, route choice and interaction.
